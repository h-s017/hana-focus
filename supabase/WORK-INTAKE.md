# 工作台交辦與免費執行

使用者在既有工作台的「交辦給 Agent」選擇專案並輸入完整指令。這是 NT$0 的確定性工具路由，沒有呼叫生成式模型，也不承諾理解任意自然語言。

| 指令 | 實際動作 | 結果 |
| --- | --- | --- |
| 整理專案進度 | 既有任務佇列；每 5 分鐘 SQL 排程讀取同專案雲端任務、統計狀態、選最多三項待處理 | 待本人審核；核准後停止，不自動產生策略交接 |
| 列出今日優先工作 | 查詢登入者最近 100 筆雲端任務，依待審核、失敗及排隊排序，最多三項 | 即時唯讀結果；不是本機工作板或完整歷史任務掃描 |
| 查詢客戶預約明細 | 呼叫既有原系統唯讀介面，需要獨立的預約查詢權限與服務端連線 | 本頁最多 200 筆；畫面明細可分頁；紀錄只存筆數，不保存客戶明細 |
| 檢查未來7天預約衝突 | 台北今天 00:00 起至第八天 00:00，使用既有日曆唯讀預覽與公開預約時段 | 前 30 筆建議與缺件數量；不改正式時段或日曆 |
| 其他內容 | 保存為需本人處理的交辦紀錄 | 明確標示尚未執行；不呼叫付費 AI、不發信、不取消預約 |

只接受上述完整指令及程式中明確列出的別名。附加的操作要求不會被忽略後執行部分指令。策略、設計產稿與素材 AI 解讀仍需另行確認可用模型及預算。

## 資料與安全

- 沿用 `hana_tasks` 與 `hana_automation_events`，沒有新平台或新資料表。
- 服務端驗證 Supabase Auth 使用者與可信 `app_metadata.hana_office_access`；客戶預約另驗證 `hana_reservation_read_access`，不信任前端 owner_id。
- RPC 僅 service_role 可執行，安全呼叫端把實際登入者身分傳入；使用者不能自行核准、改資料或排程。
- request UUID 保障重複交辦冪等；相同 UUID 改內容會衝突，不重跑來源讀取。來源結果遺失時，先更新歷史，再選範例或修改內容建立新交辦；不自動連續重試。
- 已暫停的專案保持暫停；新專案首次交辦進度時開啟免費 PM 整理，預設不授權外部素材。沿用每帳號每日 3 次、專案每日上限及單一執行中任務的保護。
- 30 秒畫面更新只讀取結果；關閉瀏覽器不影響既有每 5 分鐘伺服端排程。達上限與暫停原因會顯示。
- 客戶詳細資料僅在當次登入畫面記憶體，登出／切換帳號清除；不放 localStorage、URL、交辦紀錄或 GitHub。
- 已核准任務代表本人內部核准，不代表客戶核准、已完稿或交付。
- 沒有 Google Calendar 寫入、正式預約修改、退款、寄送通知或付費模型呼叫。

## 發布順序（需 HANA 核准本次 PR）

1. 核對完整 PR 測試結果及差異。
2. 對既有專案套用 `schema/hana-work-intake.sql` 加法 migration（新增私有 RPC、更新免費 SQL worker 與交接停止條件）。不刪除或重建資料。
3. 更新現有 `hana-automation` Edge Function，連同 `work.mjs` 及原有相依檔。保留每次請求 Auth 驗證、關閉付費呼叫；先後端後前端。
4. 合併經審核的 PR 至 `hana-focus-preview`，由帳號擁有人在原 Pages workflow 確認這次發布，不能跳過 `hana_publish_authorized` 與環境保護。
5. 登入既有工作台，用既有專案輸入「整理專案進度」，確認佇列、下一次 tick、實際任務統計與待本人審核，再測核准後沒有策略子任務。不得為測試跳過每日上限。
6. 真實客戶預約及 Google 日曆仍取決於既有安全服務端連線；離線 mock 成功不代表這些連線已設定。

## 驗證範圍

- Node 測試：精確指令、拒絕無效輸入、實際登入者、重複請求、查詢失敗、私密資料不入紀錄、台北跨日窗口及 NT$0 限制。
- PostgreSQL 17 臨時交易：RPC 權限、owner 隔離、冪等、暫停與上限、真實資料統計、待本人審核與禁止進度報告交接；交易結束 rollback。
- Playwright mock：工作台交辦、查詢明細、更新審核狀態、重複點擊、缺少連線、登出清除，保留既有登入、四角色流程、商務／教會分離與手機版測試。
- Edge Deno 類型檢查及完整靜態網站 staging 由 GitHub Actions 執行。正式端驗收另列，不能用 mock 結果替代。
