# Course and task Calendar synchronization

Prepared for HANA's requested workflow. Not a production activation or a claim of live writes.

Courses retain their existing Reservation records. Manual month synchronization exports open/enrolled course slots to managed Google events and imports time changes on those mapped events. Existing customer orders/payment rows are never changed. A Google deletion means close new intake, not refund/cancel enrolled orders. Actual cancellation of an enrolled class still requires HANA to arrange affected bookings in the original system.

An enrolled course edited/deleted in Google produces a warning in Work → 日曆同步與課程審核 and in Review Center. Approval is bound to a random review ID, the full source snapshot including enrolled count, and Google's event etag. Changes to either side invalidate the review. Conflicting edits require choosing which side wins. Rejection retains both sides. Ambiguous write outcomes stop in `unknown`; use 重新查核兩邊資料 to inspect before deciding again. No automatic write retry or background schedule is added.

Tasks stay in existing `hana_tasks`. Empty schedule means workspace tracking only; start/end dates use Asia/Taipei. Scheduled task creation attempts a targeted Google sync; existing task schedules can be edited with 儲存排程並同步 Google. Google movement changes only the mapped task's schedule. Deleting its event removes that schedule, retaining the task and work state. Completion is tracked in the workspace. A later manual month sync adds a check mark to its event title. Recurrence, all-day conversion and renaming in Google are treated as conflicts, not guesses. Single start times without a verified course end time produce `calendar_sync_duration_required` and remain unchanged.

## Release order and credentials

1. Review and release the paired Reservation PR adding `/api/focus/calendar-sync`. It is disabled without `FOCUS_SYNC_TOKEN`. Generate a dedicated strong server credential through the secure deployment/secret store, and save the same value as `RESERVATION_SYNC_TOKEN` in Supabase. Do not reuse the payment/admin token, expose it to browsers, or place it in GitHub/commands/logs. No broad admin endpoint is accepted by this bridge.
2. Review/apply `20261026161833_calendar_sync_review.sql`, then deploy the complete hana-automation dependencies and site. Both new tables have RLS enabled and no anon/authenticated privileges; only the existing authenticated Edge owner controls operate them. The migration adds nullable schedule columns and a separate `google_sync` encrypted credential kind; the existing `google` connection and encryption key remain unchanged.
3. After approval of the concrete release, enable `HANA_CALENDAR_SYNC_ENABLED=true`. Without it, no synchronization or write OAuth flow executes. No Cron activation is part of this release.
4. Add `https://www.googleapis.com/auth/calendar.events` to this application's Google consent configuration; retain the existing readonly scope and exact callback URI. Use the dedicated 同步寫入 button. HANA personally completes Google consent. Its two requested scopes are checked exactly server-side; tokens are saved encrypted in `google_sync`, never returned to the browser. Scope is a Google capability; application writes are restricted to deterministic mapped events bearing this owner's private marker, never unrelated personal events. Notifications/invitations/reminders are not enabled.
5. Verify one synthetic task and one explicit disposable course fixture in a test environment. Confirm a booked-course move creates a warning without a source write; approval applies only after unchanged-snapshot verification, while rejection and stale approval make no source changes. Check both directions and duplicate retries before selecting a real month. Manual runs apply at most 20 changed records; `more_pending` requests another run.

## Validation and recovery

Unit tests cover review gates, enrolled-count changes, Google etag changes, unbooked imports, activation and concurrency guards, task date normalization and managed Google mutation parameters. Reservation SQLite tests cover atomic CAS, last-second enrolment, closed dates, separate endpoint auth and preservation of orders/payments. PostgreSQL CI tests cover grants, lock exclusivity/expiry, mapping uniqueness and partial-schedule rejection. Existing Windows-only `social-daily.test.mjs` path separator failure is unrelated to these changes; it remains unmodified.

Disable `HANA_CALENDAR_SYNC_ENABLED` to stop sync immediately. Keep encrypted credentials/mappings/history for recovery and inspect unknown outcomes before further writes. Disabling sync does not erase previously created Google events or undo previously approved source changes. The original readonly connection remains available. Cross-system updates cannot be a single distributed transaction; Google If-Match, source database CAS, owner lock, deterministic IDs, persisted baselines and human reconciliation prevent silent blind replay.
