# 工作台介面調整

首頁原本同時展開工作、來源同步、預約、素材、自動化及測試面板，新增工作位於長頁底部。這版將日常入口分為工作、月曆、預約、素材、設定；首頁先選專案、填工作，再看今日優先與待審核成果。

- 所有入口使用既有登入與模組，只調整顯示位置與展開層級。
- 任務卡片先顯示摘要，需求與操作、前置依賴逐步展開。
- 合約原始 JSON、同步、歷史紀錄、備份及移轉收進可展開區塊。
- root 與 workspace 共用相同入口；workspace 原模組與角色插圖保留於「其他工具」。本機板仍能開啟。
- 不修改資料庫、服務端、秘密憑證、排程、預約或訂單；不變更免費分析／人工審核的限制。

## 依實際截圖修正：入口導向與部分日曆來源

- 保留原 workspace 圖示入口為主要導覽，不再收進「其他工具」。工作、品牌專案、AI Studio、教會工作、審核、執行紀錄、連線設定各有自己的 hash route；月曆、預約、素材也有獨立入口。直接開網址、重整與瀏覽器返回使用同一路由。
- 專案顯示範圍／版本／文件，Agent 顯示可執行的任務，審核只顯示成果／衝突，紀錄只顯示操作紀錄；教會入口切換至獨立工作區。Social Editor 保留自己的頁面。
- Reservation 已驗證而 Google 尚未驗證時，顯示原場次（包含關閉／額滿）與剩餘名額，明確標示私人行程未核對。sourceVerified 保持 false、proposed 空、不可核准／發布；不把原系統開放場次當作 HANA 空閒。
- monthly.mjs 將獨立 Reservation 驗證結果傳入純資料處理器；這是額外服務端程式變更，需要審查後部署 Edge Function，不是只有 Pages 更新即可。
- 連線設定提供必要欄位檢查及實際唯讀測試，兩者清楚區分。沒有加入新的 OAuth 服務、沒有修改 secrets，也沒有取得新的 Google 授權。此版本仍不提供一鍵 OAuth 登入與回呼處理器，不可把工作台網址隨意設為回呼。
- 後續 Google 連線需先盤點原 Google Cloud OAuth 應用程式，實作經審查的 OAuth state／回呼／owner 綁定及加密 token 保存，再由 HANA 在 Google 官方頁面批准 calendar.readonly；未完成前不得標記已驗證。不應要求使用者將憑證貼入聊天或用反覆重算代替授權。
